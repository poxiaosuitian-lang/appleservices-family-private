# iCloud+ 开通流程

2026-11-10：美区 50GB 方案完成真实开通验收，订阅记录和付费容量均核验通过。以下记录可复用流程，不包含账号、兑换码、付款资料或服务器原始响应。

2026-11-14：修复购买令牌失效后重复恢复旧会话的问题。新账号通过面板接口完成礼品卡入账、重新认证和美区 50GB 开通，订阅记录与实时付费容量均已核验。

## 面板操作

1. 连接 Apple 账号，确认后台在线。

   已完成验证的账号支持[自动恢复登录](automatic-login.md)：重启后核验 iCloud 和本机加密保存的 Store 会话；失效时才要求重新连接。
2. 准备适用于该账号地区的付款方式或 Apple 账户余额。面板内输入礼品卡代码并点击“确认兑换”，后端自动检查会话后提交兑换；以 Apple 返回的入账金额和余额为准。也可在 Windows Apple Music 或 Mac App Store 兑换同地区礼品卡。
3. 在 iCloud+ 页点击唯一的“开通 iCloud+ · 50GB”。自动读取实时容量和可购方案，并完成购买会话及现有订阅预检查。已有有效订阅时显示“iCloud+ 已开通”并禁用按钮；检查过程中发现已开通也立即停止。预检查不查询账户余额。
4. 预检查通过后自动弹出确认框，核对账号、币种、价格和自动续费说明，确认后才提交购买。当前美区路径限定 50GB、USD 0.99/月；价格变化时需要重新核对，不使用旧报价提交。
5. 成功必须同时核验订阅及付费容量。面板显示“iCloud+ 已开通”和容量，并禁用重复开通；重载页面仍以查询结果为准。

官方说明：https://support.apple.com/zh-cn/118242 。部分购买仍可能要求登记付款方式，账户余额不保证所有账号都免绑卡。

## 接口与失败处理

- `storage-info`：只读容量；`storage-purchase-prepare-us`：只读检查容量、报价及订阅，并按需认证 Store。
- `storage-skill-purchase-us`：经用户确认的真实购买；保留现有后端的价格、账号、会话及已有订阅检查。
- 只有 `purchase-completed` 且订阅和付费容量都核验成功，才报告完成。HTTP 200 本身不代表购买成功。
- 返回付款提示或错误码 3015 时，不应仅凭错误码断言缺卡或余额不足；检查官方付款/余额状态，处理后重新预检查。
- 返回购买令牌失效（2034）时，废弃该令牌并更新本机加密会话，避免预检查再次恢复旧令牌。面板仅保留“开通 iCloud+ · 50GB”：每次点击先读取容量与可购方案，美区随后执行购买会话和现有订阅预检查；展示已核验月费，用户确认后仅提交一次购买。令牌失效后再次点击也先走完整检查，不自动重放购买。
- 超时、断线或结果不明时先查询容量和官方订阅记录，不自动重放购买请求。

## 已验证的边界

现有 Store 登录与购买流程可以完成开通。[礼品卡协议兑换](gift-card-protocol.md)使用项目自己的会话读取真实桌面兑换页并提交其表单；已完成真实入账验收。官方客户端仍是可用的兑换入口。面板只在用户确认后短暂处理代码，不保存或记录代码，也不在兑换后自动购买订阅。

Windows 官方客户端曾出现登录连接错误，临时直连对照后登录成功。这不是所有失败的统一原因；程序不自动修改系统代理。安装官方客户端时核对实际包位置与已有运行库，不能仅凭默认应用安装卷判断所有文件位置。

## 验证

后端：`go test ./internal/dashboard ./cmd/trusted-device . ./icloud`

离线浏览器回归：安装 Playwright 后运行 `node tools/test-icloud-purchase-ui.cjs`。可用 `PLAYWRIGHT_MODULE` 指定已有模块路径、`BROWSER_CHANNEL` 指定 Edge 等浏览器；测试拦截所有请求，不接触真实账号或购买接口。
