# 双重验证与自动恢复登录

完成双重验证后，本机保存账号独立的设备身份与登录会话。重启一键启动程序时，后台自动恢复已保存账号，不要求保存 Apple 账号密码。

## 恢复范围

- iCloud：成功登录及续期时保存已被 Apple 接受的 delegate 会话。启动时读取设备列表、查询容量，实际通过后才显示在线。
- 旧版本只有 GSA 会话时，可以尝试用已验证令牌补齐 delegate；Apple 拒绝时需要带密码重新连接一次。损坏或账号不匹配的 delegate 文件不会走这个补齐路径。
- Store：Windows 使用当前 Windows 用户的 DPAPI 加密保存商店会话，保存在账号目录的 `store-session.dpapi`，不包含密码、验证码、礼品卡代码或待提交交易。恢复时核对 Apple 账号、DSID 和本机商店硬件标识，再通过只读订阅查询验证。保存超过 24 小时的会话不恢复；Apple 也可能提前使令牌失效。
- 已绑定账号再次遇到 Apple 的可信设备验证码挑战时，最多尝试一次本账号原生设备码。首次登录、短信挑战、身份不匹配以及无法完成的验证仍需手动处理；不会自动批准其他设备发来的登录请求。

## 失效处理

修改密码、撤销设备或 Apple 要求重新认证后，面板会提示重新连接。双重验证开启不代表永不过期，也不能替代 Apple 明确要求的短信或其他确认。

自动恢复不提交购买、兑换、取消订阅或条款确认。新礼品卡实际入账仍需用未兑换卡单独验收；旧卡不能再次提交。恢复商店会话不会恢复上一次兑换的确认 ID。

会话文件、设备身份、加密商店凭据和诊断日志都属于本机私有运行数据，不能提交 Git。退出账号时同时清除 GSA、delegate 和加密 Store 会话；单纯停止后台保留会话供下次启动使用。

## 验证

`go test . ./icloud ./cmd/trusted-device ./internal/dashboard ./internal/control`

覆盖账号绑定、旧会话补齐、Apple 拒绝、保存失败、设备码单次尝试、DPAPI 加解密及篡改/过期拒绝。真实验收应在建立商店会话后重启后台，以无密码启动、设备列表、实时容量及兑换会话准备作为证据，不使用真实购买或兑换进行登录测试。

2026-11-11 实测：旧版本只保存的 GSA 令牌在补换 delegate 时被 Apple 拒绝，使用现有账号凭据重连一次后保存成功。随后重启后台且不提供密码，iCloud 与 Store 会话均恢复，设备推送连接正常；实时容量为 50GB，礼品卡准备返回就绪，续期查询通过。本次未提交购买或兑换，也未触发新的人工短信挑战。
